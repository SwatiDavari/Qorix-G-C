Standards & conventions
===========================

Structure
------------

Every Qorix documentation project keeps the same four top-level
sections in the same order: Overview, Getting started, Standards,
Contributing. Project-specific content is added as additional
sections after these four, not in place of them.

Writing
----------

Use sentence case for headings. Keep the first section of every page
short enough to read without scrolling. Prefer short pages linked from
a toctree over one long page.

Versioning
-------------

Set ``release`` in ``conf.py`` to the project's current version. Tag
documentation releases alongside code releases so a reader can match a
doc version to the software version it describes.
